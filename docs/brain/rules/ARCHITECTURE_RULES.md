# Architecture Rules

> **Governs structural decisions and module organization**

---

## Directory Responsibilities

| Directory | Responsibility | Rules |
|-----------|---------------|-------|
| `src/app/` | Next.js routes, layouts, global CSS | One layout.tsx, one page.tsx per route. API routes go in `src/app/api/`. |
| `src/components/ui/` | shadcn/ui primitives | Only generated by `npx shadcn-ui add`. Do not hand-modify unless absolutely necessary. |
| `src/components/` | Custom application components | Place new shared components here (e.g., section components, custom cards). |
| `src/ai/` | Genkit AI flows and configuration | All AI logic here. Server-only. Never import into client components directly. |
| `src/lib/` | Pure utility functions | Must be side-effect free. `utils.ts` contains `cn()`. |
| `src/hooks/` | Custom React hooks | Client-only hooks. Follow `use-` naming convention. |
| `public/` | Static assets | Images, PDFs served at root URL. File names are public URLs. |

---

## Dependency Direction

```
src/app/        → can import from src/components/, src/lib/, src/hooks/
src/components/ → can import from src/lib/, src/hooks/, src/components/ui/
src/ai/         → can import from src/lib/
src/lib/        → no internal imports (pure utilities)
src/hooks/      → can import from src/lib/
```

**Rule**: Lower layers must not depend on higher layers. `src/lib/utils.ts` must never import from `src/components/`.

---

## Component Rules

1. **Client Components** (`'use client'`): Only for components requiring `useState`, `useEffect`, event handlers, or browser APIs.
2. **Server Components** (default): Prefer for static content, layout, and data-fetching wrappers.
3. **Sub-components** (`ProjectCard`, `ExperienceCard`, `Logo`): Currently inline in `page.tsx`. Should be extracted to `src/components/` when refactoring.

---

## Introducing New Routes

If sub-pages are added (e.g., `/blog`, `/projects/[id]`):
1. Create `src/app/[route]/page.tsx`
2. Add nav link to the header navigation in `layout.tsx` or `page.tsx`
3. Document the new route in [REPOSITORY_MAP.md](../REPOSITORY_MAP.md)
4. Add a feature entry to [FEATURES.md](../FEATURES.md)

---

## Introducing AI Features

1. All AI logic goes in `src/ai/` — never in page components
2. Define flows using `ai.defineFlow()` from `src/ai/ai-instance.ts`
3. Import flows in `src/ai/dev.ts` for Genkit dev server
4. Call flows only from Server Actions or API Routes — never directly from client components
5. See [directory-rules/ai.md](../directory-rules/ai.md) for detailed instructions

---

## Styling Architecture Rules

1. **Do not introduce a second design system.** shadcn/ui is the component system. Tailwind is the styling system.
2. **CSS custom properties** in `globals.css` are the single source of truth for all design tokens.
3. **Dark mode**: Modify `globals.css` `.dark {}` block — do not add custom dark: variants in individual components when a design token change would be more appropriate.
4. **Custom animations**: Add to `tailwind.config.ts` `keyframes` + `animation` blocks. Do not add `@keyframes` in `globals.css`.

---

## File Size Rules

- `page.tsx` is currently 2000+ lines — a known debt item. Do not add more sections without considering extraction.
- New sections should be extracted as separate files in `src/components/sections/`.
